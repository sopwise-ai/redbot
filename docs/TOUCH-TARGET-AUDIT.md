# 触控目标审计（2026-11-03）

> 范围：移动端 390×844，`/topics/news/` 与抽屉导航。
> 方法：`getBoundingClientRect()` 实测渲染尺寸，不是设计稿估算。
> 本文只记录现状与建议，不改代码。

## 标准对照

| 标准                    | 最小尺寸     | 说明               |
| ----------------------- | ------------ | ------------------ |
| WCAG 2.2 SC 2.5.8（AA） | 24×24 CSS px | 低于此值才构成失败 |
| Apple HIG               | 44×44 pt     | 舒适触控的行业参考 |
| Material Design         | 48×48 dp     | 同上               |

## 实测

| 控件               | 尺寸             | WCAG AA | Apple 44 |
| ------------------ | ---------------- | ------- | -------- |
| 主区域按钮（pill） | 高 36，宽 60–220 | ✅      | ❌       |
| 顶栏「菜单」       | 28×28            | ✅      | ❌       |
| 主题切换           | 32×32            | ✅      | ❌       |
| 主题页「分享」     | 32×32            | ✅      | ❌       |
| 主题页「编辑」     | 32×32            | ✅      | ❌       |
| 抽屉「关闭」       | 32×32            | ✅      | ❌       |
| 抽屉主题行         | 高 36            | ✅      | ❌       |
| 搜索框             | 高 40            | ✅      | ❌       |
| 页脚「回到顶部」   | 84×28            | ✅      | ❌       |

补充：按钮墙相邻按钮间距 8px，36px 高度在 390px 宽的网格里没有误触报告；文字的对比度问题已在既有 `contrast.ts` 覆盖范围之外，本表不含颜色。

## 结论

1. **全部控件都满足 WCAG 2.2 AA（≥24px）**，没有合规阻塞。
2. 没有任何控件达到 Apple HIG 的 44px；这是「密度优先」的既有取舍，不是遗漏。
3. **不建议把按钮墙从 36 提到 44**：189 条会多出约 1500px 页面高度，首屏可见按钮从约 30 个降到约 24 个，直接伤害「一页按钮」的核心体验。
4. 如果要改善手感，性价比最高的是**给顶栏图标按钮加不可见的命中区域**（`::after` 负 inset，视觉尺寸不变，命中区 44×44），而不是放大视觉尺寸。
5. 页脚「回到顶部」是低频动作，28px 可接受；如要调整，同样用命中区扩展。
