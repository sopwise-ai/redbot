# RedBot 下一步开发计划

> 基于 2026-11-02 对本地生产构建（`out/`，<http://localhost:4173/>，27 个页面）的实际浏览：
> 桌面 1440×900、移动 390×844、浅色 / 深色、键盘 Tab 走查、搜索与足迹的真实操作。
> 文中的数字都是当场用 `getBoundingClientRect` / `getComputedStyle` / 截图像素采样量出来的，不是估计。
> **本文只提建议，不改源码**；所有方案都按 AGENTS.md 的既有约定给（无运行时外部请求、优先 shadcn/ui、足迹只存本地、分类在路径里、动效尊重 `prefers-reduced-motion`）。

## 0 结论

1. 产品已经有明确身份：一屏说清「是什么」，189 个按钮 6 列等宽、首屏可见 71 个、切分类零请求。**这部分不要动。**
2. 真正卡住的不是视觉，是「找得到」这条主链路的三个断点：**搜索状态不可恢复**（分享 / 刷新 / 后退全丢）、**召回不足**（`bilibili`、`weibo`、`模板` 全部 0 命中）、**移动端切完分类看不到自己在哪**。
3. 所以下一步不是加功能，而是补主链路的可靠性。「任务入口 / 我的 / 万级目录」这类扩张，在语料只有 189 条、且办公任务类站点 0 条的前提下不具备条件——先量化缺口，再决定要不要动结构。

### 1.3 三个断点的根因（读代码确认过）

- **搜索不可恢复**：`app-shell.tsx` 里 `query` 初始化恒为 `""`，从不读 `location.search`；`searching` 为 false 时那条 effect 会把 `/search/` 改写成 `/`。所以「URL 是状态」这件事只做了写、没做读。
- **后退停在空搜索**：`popstate` 只匹配 `/^\/topics\/([a-z0-9-]+)\/?$/`，没有 `/search/` 分支，也没有「退出搜索态」的路径。
- **移动端状态不可见**：chip 行是一个 `ScrollArea`（内容宽 1406px、视口 390px），切换分类只改 `aria-checked`，没有把选中项滚进视野。

## 2 用户旅程断点

主链路：**打开首页 → 找到目标 → 跳出去 → 下次回来**。

| 环节                             | 现状                              | 断点                                                                                     | 严重度       |
| -------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------- | ------------ |
| ① 打开 → 明白这是什么            | H1 + 副行 + 信任行，一屏内成立    | 无                                                                                       | —            |
| ② 记得名字 → 输入                | `⌘K` / 点顶栏都能搜，即搜即显     | 拼音与英文名 0 命中（`weibo`、`bilibili`）                                               | 高           |
| ③ 想不起名字 → 扫                | 6 列按钮墙 + 色点分段，滚动无锚点 | 滚到第 15 行时不知道自己在哪个组——这是 DESIGN-LOG 第 43 轮刻意的取舍，**不建议改回标题** | 中（接受）   |
| ④ 手机上换分类                   | 抽屉 / 吸顶 chip 两条路           | 抽屉选完，chip 行不跟随，整行无高亮                                                      | 高           |
| ⑤ 跳出去                         | 新标签打开 + 记足迹               | 无                                                                                       | —            |
| ⑥ 下次回来                       | `/history/` 只显示名字            | 存了次数与时间却不显示，「回访价值」没兑现；空态只有一句话，没有动作                     | 中           |
| ⑦ 失败恢复（刷新 / 分享 / 后退） | 三条路径都坏                      | 搜索态与 URL 脱钩，用户被留在空视图                                                      | **最高**     |
| ⑧ 找不到时                       | 空态给「清除搜索 / 建议收录」     | 但用户真正想问的是「那我去哪找」——语料里没有对应站，空态给不了替代                       | 高（内容层） |

一句话：**②④⑦ 是工程问题，⑧ 是内容问题，⑥ 是价值兑现问题。** 优先级按这个顺序。

## 3 下一步开发计划

### P0（本周，3 项 + 1 个决策）

#### P0-0 量化「任务词 → 命中」的语料缺口（决策输入）

- **要解决的用户问题**：STRATEGY.draft 想服务「知道要做什么、不知道去哪」的办公人群，但现在 `模板`、`报告` 搜 0 条；189 条里没有天眼查、企查查、Canva、稿定、石墨、Notion、WPS、百度文库、新榜。**在补语料之前做任务入口，等于把空页面做得更漂亮。**
- **具体方案**：写一个一次性脚本（`tsx scripts/task-coverage.ts`，可不入库），复用 `src/lib/search.ts` 的 `createSearchIndex`，跑 20 个高频任务词（查公司、找模板、找素材、找数据、找报告、找课程、查招聘、查房价、查航班、查专利…），输出每个词的命中数与前 3 个结果。若 ≥15 个词命中 0，结论是「语料不支持任务维度」，任务入口推到 P2 之后；若命中过半，再评估是否新增任务字段。
- **工作量**：小（半天）
- **风险与取舍**：这只产出判断，不产出功能。注意别顺手把结果写进 `data/`——语料调整要先过 `LIMITS`（单类 ≤20）与「desc 写使用时机」两条规矩；各类配额合计还剩 151 个空位（工具 11、产品设计 8、学习 10、财经 4）。
- **验收**：一张 20 行 × 3 列的表（词 / 命中数 / 前三条），放进本文件或 `docs/` 下另开一页。

#### P0-1 搜索状态与 URL 双向绑定

- **要解决的用户问题**：把搜索结果发给同事，对方打开是空的；自己刷新一下也丢了；按后退被困在空搜索页。这三件事都发生在主链路上。
- **具体方案**：
  - 新增纯函数 `resolveRouteState(pathname, search)` → `{ view, active, query }`，放 `src/lib/route-state.ts`，配单测（`/search/?q=x` → query=x；`/topics/tech/` → active=tech；`/` → all）。
  - `AppShell` 首帧用一个 `useEffect` 读 `location.search` 初始化 `query`（静态导出，不能指望服务端注入）；把 `originPath` 初始化为 `document.referrer` 同源路径，取不到时退回 `/topics/<上一分类>/`，再退回 `/`。
  - `popstate` 增加 `/search/` 分支：有 `q` 就 `setQuery(q)`，没有就 `setQuery("")` 并回源；同时处理「从搜索态后退到非搜索路由」的退出。
  - 保持 `/search/` 是**状态**而不是新路由段（不改成 `/search/[q]`），否则会丢掉「边打边筛」的手感。
- **工作量**：小（0.5 天，含单测）
- **风险与取舍**：首帧 `setQuery` 会再触发一次 `replaceUrlQuietly`，注意 AGENTS 记的那个坑——它绕过了 Next 的 `replaceState` patch，否则每打一个字输入框就失焦。另外 `q` 不要进 `metadata`（页面已 `robots: noindex`），避免分享链接被搜索引擎收录成空页。
- **验收**：直接打开 `/search/?q=新闻` → 23 条且输入框有值；刷新保持；无痕窗口打开同一链接可复现；从 `/topics/finance/` 搜索后按后退 → 回到 `/topics/finance/` 且侧栏高亮财经。

#### P0-2 移动端分类 chip 跟随当前分类

- **要解决的用户问题**：在抽屉里点了「工具」，页面切过去了，但吸顶那一行还停在「全部 / 新闻 / 科技 / AI / 财经」——**用户看不出自己在哪个分类**，也无法判断要不要再切。
- **具体方案**：
  - 分类变化后，对 `[role="radio"][aria-checked="true"]` 的 chip 调 `scrollIntoView({ inline: "center", block: "nearest", behavior: reduced ? "auto" : "smooth" })`；`block: "nearest"` 是必须的，否则会把整页顶上去。
  - chip 行两端加 12px 渐隐（`mask-image`），滚动到两端时对应一侧的渐隐消失，给「这行还能滑」一个视觉信号（现在只能靠右侧被切掉半个 chip 猜）。
  - 复用现有的 `prefers-reduced-motion` 判断，不要新写一份。
- **工作量**：小（0.5 天）
- **风险与取舍**：`scrollIntoView` 与 View Transitions 同帧执行会打架——放在过渡完成之后（`startViewTransition` 的 `finished` 回调）或 `requestAnimationFrame` 里。渐隐是新增视觉，必须极淡，别变成一条装饰线。
- **验收**：390px 下从抽屉选最后一个分类「工具」，chip 行自动把「工具 9」滚到中间且高亮；手指再滑动时渐隐随位置变化。

#### P0-3 把 11–12px 辅助文字的对比度拉回 4.5:1

- **要解决的用户问题**：侧栏计数、「更新于」、分组标签、信任行在浅色下只有 1.75–2.88:1，深色下 2.19–4.33:1。低视力用户读不到，普通用户在大屏上也要凑近看。这与 PRODUCT-DESIGN §9 自定的「对比度 ≥ 4.5:1」直接冲突。
- **具体方案**：根因是 11px 文字上叠了 `/40 /50 /60 /70` 的透明度后缀（`app-sidebar.tsx` 4 处、`shell-header.tsx` 2 处、`topics-index.tsx` 3 处、`site-footer.tsx` 1 处）。改成实色 `text-muted-foreground`：实测浅色 5.51:1、深色 8.02:1，一次改完两侧都达标。层级改由**字号（11 vs 14）与字重**承担，不靠透明度。
- **工作量**：小（0.5 天）
- **风险与取舍**：11px 计数变深后会跟正文抢注意力——只对 11px 及以下的辅助信息生效，正文的 `foreground/90` 不动；改完深色单独看一遍，暗底上实色可能显得过亮，必要时给深色单独一档（`dark:text-muted-foreground` 保持不变即可）。
- **验收**：新增 `src/lib/contrast.ts`（oklch → sRGB → WCAG ratio，纯函数）+ 单测，锁住 `muted-foreground` 在 `background` / `card` / `sidebar` 三种底上的比值 ≥ 4.5，浅深各一组。

### P1（下个迭代，4 项）

#### P1-4 搜索召回：别名与拼音首字母

- **要解决的用户问题**：用户记得「bilibili」不记得「哔哩哔哩」，记得「zhihu」不记得「知乎热榜」。现在这些输入全部 0 命中——**这是「找得到」最直接的一次失败**。
- **具体方案**：
  - 新增 `src/lib/aliases.ts`：`Record<linkId, string[]>`，只收「名字里没有、但用户一定会打」的写法——拼音首字母（`wb`、`zh`、`db`、`blbl`、`xhs`）、英文名（`weibo`、`bilibili`、`douban`、`zhihu`）、旧名。中文名本身能被 fuse 命中，不必重复。
  - `createSearchIndex` 里给 fuse 的 `keys` 加一项 `aliases`，权重 0.8（低于 `name`，高于 `desc`），不改变现有排序结构。
  - 构建期校验（沿用「构建期失败优先」）：alias 的 key 必须存在于 `links.json`，否则 `npm run validate` 直接失败。
- **工作量**：中（1 天，主要成本是给约 60 条补别名）
- **风险与取舍**：别名是第二份真相，天然会腐坏 → 用单测锁「key ⊆ links.id」和「alias 不与其他站点的 name 完全相同」。**不要引入拼音库**（pinyin-pro 一类约 30KB 运行时），189 条规模下手写别名更小也更快。
- **验收**：`wb` → 微博热搜；`zhihu` → 知乎热榜；`bilibili` → 哔哩哔哩；`xhs` → 小红书；空态文案不变。

#### P1-5 键盘流补全（兑现 PRODUCT-DESIGN §2.2）

- **要解决的用户问题**：文档承诺「键盘优先」，但搜索框排在第 24 个 Tab 位、`/` 不聚焦、结果列表按 `↑↓` 没反应。对每天用的人来说，这决定了它是「工具」还是「网页」。
- **具体方案**：
  - 全局 `keydown`：`/` 且焦点不在 `input` / `textarea` / `[contenteditable]` 时，聚焦搜索框（和 `⌘K` 复用同一个函数，不要两份实现）。
  - 搜索结果加 `activeIndex`：`↑↓` 移动、`Enter` 打开（`window.open` + `recordVisit`，与 `LinkPill` 的点击路径一致）、`Esc` 先清高亮、再按一次回源（两级退出，与 §2.2 的「逐层退出」一致）。
  - 高亮样式**复用现有 `focus-visible` 那套**（`bg-accent` + `ring-2 ring-ring/25`），不新增颜色；给输入框加 `aria-activedescendant`，`aria-live` 播报「第 2 个，共 23 个」。
- **工作量**：中（1–2 天）
- **风险与取舍**：`↑↓` 要 `preventDefault` 阻止页面滚动，否则一按就跳；移动端不启用（没有物理键盘，且会和软键盘抢）；不要把 189 个按钮都改成可聚焦列表项——只在搜索态加这一层。
- **验收**：纯键盘完成 `⌘K` → 输入 → `↓↓` → `Enter` 跳转，焦点与滚动都不乱；`/` 在输入框内不会重复聚焦。

#### P1-6 足迹兑现：让「回来」有价值

- **要解决的用户问题**：`/history/` 现在只显示名字，和侧栏「全部」的区别只是顺序。存下来的 `count` / `at` 一点没用上；空态只有一句话，没有动作。
- **具体方案**：
  - 不改布局的前提下，把 `count` / `at` 放进按钮的 `title` 与 `aria-label`（现有 `title` 已被 `desc` 占用，合并成「点过 4 次 · 最近 3 天前 · 十分钟前的全网议题」）。
  - 页头副行改一句更有信息量的话（例如「最近点过的排在最前」），行内只留「3 个」，去掉重复。
  - 空态补一个动作按钮「随机一个」，复用侧栏的随机逻辑（抽成 `pickRandom()`，两处共用）。
  - 0 条时侧栏不显示徽章（DESIGN-LOG 第十阶段的取舍记录里写过「为空时不显示徽章」，现在显示「0」，与记录不一致）。
- **工作量**：小–中（0.5–1 天）
- **风险与取舍**：**不要顺手做成「我的 / 收藏 / 分组 / 场景包」**——那是 STRATEGY v2 的账号向扩张，需要跨设备才有价值，而跨设备需要账号，账号是红线。足迹的定位是「被动记录」，别把它升级成第二个书签管理器。
- **验收**：点过 2 次的站，`title` 里能看到「点过 2 次」；清空后空态有可点的动作；0 条时侧栏无徽章。

#### P1-7 文案去重与搜索态侧栏状态

- **要解决的用户问题**：同一个数字 / 同一句话在一屏里出现两三次，读者要花力气判断「这是不是不同的事」。
- **具体方案**：搜索页删掉「找到 N 个结果」这句（徽章已经说了），副行保留「在全部 189 个信息源里查找」；足迹页副行与行内二选一；页脚去掉「189 个信息源 · 17 个主题」（与页头右侧重复），只留「更新于」与 MIT；搜索态侧栏不再给「全部」加红色 active 底（红色只留给「当前分类」，而搜索是全站的，没有当前分类）。
- **工作量**：小（0.5 天）
- **风险与取舍**：页脚那行统计兼作「规模信任信号」，删之前先做 P2-11（补 L3 信任行），否则页脚会只剩一个 MIT。
- **验收**：搜索「新闻」时，页面上「23」只出现一次；足迹页「按最近使用排序」只出现一次；搜索态侧栏无红底。

### P2（观察，4 项）

#### P2-8 移动端触控目标

- **问题**：36 / 32px 的按钮与行高低于 44×44 的舒适区，拇指在移动中容易点错。
- **方案**：只把 chip 行与抽屉行提到 40px（`h-10`），按钮墙保持 36px 不动——等宽网格的密度是产品的核心资产，一动全站变长。
- **工作量**：小（0.5 天）
- **取舍**：390px 下首屏可见按钮会从 30 降到约 26，页面高从 4593px 涨到约 5000px。**必须真机验证再定**，不要在桌面上拍板。

#### P2-9 主题索引的箭头语义与孤儿卡

- **问题**：17 个内部跳转用了 `ArrowUpRight`（外链 / 新标签语义），点下去却是站内导航；3 列网格下「资讯」4 条会留一张孤儿卡。
- **方案**：内部卡换 `ChevronRight`；网格改 `repeat(auto-fill, minmax(280px, 1fr))`，让列数随宽度走。
- **工作量**：小（0.5 天）
- **取舍**：`ArrowUpRight` 在按钮墙上是对的（真的是外链新标签），两处语义不同，不要为了统一而统一。

#### P2-10 404 页给一个搜索出口

- **问题**：`/nonexistent/` 只有「回到首页」和 GitHub。对一个目录站，用户到这里最可能想做的事是「那我搜一下」。
- **方案**：在 404 里放一个受控搜索框（复用顶栏同一个组件），输入后跳 `/search/?q=`——依赖 P0-1 先把直链修好。
- **工作量**：小（0.5 天）
- **取舍**：404 目前是无外壳的独立版式，加搜索框会引入一次组件依赖；如果嫌重，退一步只加「按主题浏览」链接也可以。

#### P2-11 页脚补 L3 信任行

- **问题**：PRODUCT-DESIGN §2.7 要求页脚固定「免费开源 / 无跟踪 / 不卖位置」，现在页脚只有 MIT，信任行只出现在首页副行下面。
- **方案**：页脚左侧加一行 `text-xs` 的 `site.trust`（文案来源不变，仍是 `src/lib/site.ts` 的三层结构）。
- **工作量**：小（0.5 天）
- **取舍**：与首页信任行重复——首页说的是「是什么」，页脚说的是「凭什么信」，位置不同、作用不同，可以接受；但不要因此造第四句卖点。

## 4 明确不建议做的事

| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 内容聚合 / 阅读器 / 账号 / 推荐算法                 | 定位红线。做了就不再是「快捷入口」，而是又一个信息流产品。                                                                                                                      |
| 「我的」三 tab、场景包、万级分层目录（STRATEGY v2） | 在 189 条、单人维护、无账号的前提下，做出来就是「第二个书签管理器」；跨设备价值要账号来兑现，而账号是红线。先解决覆盖面，再谈管理层。                                           |
| 任务维度 / 任务 chip / 任务页                       | 语料里 0 条办公任务站（天眼查、企查查、Canva、稿定、石墨、Notion、WPS、百度文库全部没有），`模板`、`报告` 搜索 0 命中。入口做得再好，点进去是空的，比没有更伤。先跑 P0-0 量化。 |
| 把分区标题加回来                                    | DESIGN-LOG 第 43 轮已经因为「页面被割裂」删掉，色点分段 + 32px 段间距是当前最优解。扫读效率的损失是已知代价。                                                                   |
| 条目悬浮卡（PRODUCT-DESIGN 5.3）                    | 180px 网格里 hover 卡片会遮住相邻按钮；移动端没有 hover，要另做长按。收益低于成本，`title` + `aria-label` 已经够。                                                              |
| 引入拼音库做全文拼音检索                            | 189 条规模下，手写别名表（P1-4）更小更快，也不会为 30KB 运行时付首屏成本。                                                                                                      |
| 任何形式的统计 / 埋点（含「匿名聚合」）             | 违反「无外部请求」，也会让信任行那句话变成不实陈述。验证方式见第 5 节。                                                                                                         |
| 把首页搜索框做大、做成第一屏主元素                  | DESIGN-LOG 第 68 轮已经把搜索收回顶栏。决定「找得到」的是召回质量与键盘路径，不是输入框尺寸。                                                                                   |

## 5 衡量指标建议

约束：没有统计代码、没有第三方脚本、不能新增外部请求。所以指标只能分三类，**并且要诚实承认第三类基本不可得**。

### A 构建期 / CI 可断言（不依赖用户数据）

| 指标         | 怎么测                                                                            | 现在                      | 目标                     |
| ------------ | --------------------------------------------------------------------------------- | ------------------------- | ------------------------ |
| 对比度       | 新增 `src/lib/contrast.ts` + 单测，算 token 组合的 WCAG 比值                      | 11px 文字 1.75–2.88（浅） | 全部 ≥ 4.5               |
| 搜索直链可用 | `resolveRouteState()` 单测                                                        | 无此函数                  | `/search/?q=x` → query=x |
| 别名完整性   | 单测：alias 的 key ⊆ `links.id`，且每条至少命中 1 条                              | 无别名                    | 0 孤儿                   |
| 死链率       | `npm run check:links`（已有，每周 CI）                                            | —                         | 不上升                   |
| 首屏密度     | 构建后断言 `out/index.html` 里 `target="_blank"` ≥100（已有）+ 新增 gzip 体积上限 | 189 条 / 31KB gzip        | 条目不减、体积 ≤40KB     |
| 数据配额     | `npm run validate`（已有）                                                        | 189 / 340                 | 不越界                   |

### B 人工走查清单（发版前 10 分钟，8 条）

建议新增 `docs/QA-CHECKLIST.md`，每次发版照做，每条给「操作 → 预期」：

1. 桌面 1440：首屏能看见 ≥60 个按钮，189 条无截断。
2. 移动 390：首屏能看见 ≥25 个按钮，chip 行可横滑。
3. 深色：11px 辅助文字仍可读（对照浅色不应明显更淡）。
4. 键盘：`⌘K` 聚焦 → 输入 → `↓↓` → `Enter` 跳转；`/` 也能聚焦。
5. 搜索直链：新开无痕窗口打开 `/search/?q=新闻`，有结果。
6. 刷新：搜索后 F5，查询还在。
7. 后退：从分类页搜索后按后退，回到原分类。
8. 404：`/nonexistent/` 有出口；页脚有信任行。

### C 本地可选记录（不上传、不新增请求）

- `redbot:history` 已经能算出「人均足迹条数」「搜索后是否点击」。但这些数据**只能烂在用户自己的 localStorage 里**：没有汇总渠道，也没有导出入口。现在去做「本地统计面板」是自欺——它不会告诉你有多少人用，只会多一屏没人看的数字。
- 如果确实需要方向性结论，用**可用性测试**替代埋点：找 5 个人，各做 3 个任务（「找雪球」「找哔哩哔哩」「查一家公司」），记录成功率与用时。1 小时成本，比任何前端统计都准。
- 唯一值得本地存的是「搜索词是否命中 0」——如果将来做导出，这份清单就是补语料的直接输入；现在先不做。
