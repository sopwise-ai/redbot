# 设计迭代记录

RedBot 首页从「卡片表格」演进到「高密度索引面板」的过程。每一轮都遵循同一循环：**改 → 构建 → 截图 → 评审 → 再改**，评审由一位独立的设计视角给出（10 分制）。

## 起点

单列布局 + 顶部 wrap 成两行的 pill 过滤 + 双行卡片（名称 + 描述）。功能完整，但信息语法只有一种：容器 + 两行文字，重复 189 次。

独立评审：**6.0 / 10**。诊断原话：「工程完成度高，设计判断缺席。」

## 关键决策与理由

**为什么是左侧导航，而不是顶部 pill**
17 个分类在 1200px 下要换行成两行，常驻占 72px；侧栏可以容纳 30+ 个分类而不增加首屏成本，且移动端由 `Sidebar` 免费提供 Sheet。

**为什么去掉条目的常驻边框**
189 个等大矩形会形成网格噪声，让页面读起来像表格。边界改由 hover 态（`bg-accent`）和常驻箭头承担——产品隐喻是「按钮」，不是「卡片」。

**为什么用 subgrid**
连续栅格能消除「最后一行只剩一个」的孤儿卡，但 `sticky` 需要正确的包含块。`grid-template-columns: subgrid` 同时满足两者：section 是真实盒子（吸顶随 section 结束而让位），子元素又对齐父级列。

**为什么不用逐条 Tooltip**
189 个 Radix Tooltip 会显著增加组件树。用原生 `title` + `aria-label` 达到同样目的（桌面悬停显示说明，读屏可读），零成本。

**为什么深色用 `foreground/85`**
189 行纯白字压在 `#0a0a0a` 上等于 189 个东西同时在喊「看我」。降低静止态亮度，hover 时回到全亮，让「注意」变成一种状态而不是默认。

## 已知取舍

- **Sheet 打开时的焦点**：Radix 会自动聚焦第一个可聚焦元素（「全部」），红色焦点环与选中态叠加，看起来像错误态。修它需要改 shadcn Sidebar 内部或包一层自定义逻辑，暂时接受。
- **移动端 2 列时的箭头**：箭头贴在单元格右缘，左列的箭头会落在屏幕中间。视觉上可接受，未做特例。
- **`pt-12` 的分区间距**：让「组内极密、组间极疏」成立，代价是单屏可见分区数从 4 个降到 3 个。

## 第二阶段：对齐 chat.deepseek.com 的表面语言

参照物不是凭印象，而是打开 chat.deepseek.com 直接量到的：纯白底、`#f9fafb` 的输入框、48px 高、28px 圆角、1px 边框、**零阴影**。据此重做了表面层。

| 轮  | 改了什么                                                                           |
| --- | ---------------------------------------------------------------------------------- |
| 12  | 引入冷灰 token（foreground/border/muted 带一点蓝相），底色改纯白，圆角 10 → 12px   |
| 13  | 搜索框改成 40px 胶囊（`rounded-full` + `bg-muted` + 透明边框），聚焦时边框变品牌红 |
| 14  | 条目从「纯文字」改成 `h-10` + `rounded-xl` 的悬停块，hover 时 `bg-accent`          |
| 15  | 分区之间加 1px 发丝线，上下各留 20px，让「组」真正成立                             |
| 16  | 侧栏底色压深到 `oklch(0.973)`，与内容区形成层次；页面滚动条改细                    |
| 17  | 搜索结果换成「带说明的行」：名称 + 分类徽章 + 一句话 + 目标域名 + 箭头             |
| 18  | 空状态给两个明确出口（清除搜索 / 建议收录），按钮改胶囊                            |
| 19  | 箭头 hover 位移 2px，`transition-all` 统一动效                                     |

关键判断：**DeepSeek 的质感来自「克制的表面」而不是装饰**——没有阴影、没有渐变、没有彩色块，只有一致圆角、极浅边框、恰当留白。所以这一阶段没有加任何新组件，只调 token 和间距。

### 第三阶段·续：真正的进出场

| 轮  | 改了什么                                                                              | 为什么                                                                  |
| --- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 24  | 分类切换改用原生 **View Transitions**（`document.startViewTransition` + `flushSync`） | CSS 只能做「进场」，退场需要旧 DOM 还在；原生方案零依赖就能拿到两帧快照 |
| 25  | 只给 `main` 命名 `view-transition-name: catalog`，并把 `root` 的交叉淡入关掉          | 默认会把侧栏和页脚一起淡掉；现在只有内容区参与                          |
| 26  | 旧内容 110ms 退场、新内容延迟 70ms 再 180ms 进场                                      | 同时交叉会出现两版文字重影（慢放 2 秒时非常明显）                       |
| 27  | 移动端吸顶标题收紧到 `pt-2 pb-1.5`                                                    | 56 顶栏 + 48 chips 之后，再占 42px 太重                                 |

## 第四阶段：从「分区索引」到「按钮墙」

用户反馈：分区让人感觉页面被割裂，按钮应当不定宽、居中、有形状，搜索也只是一个过滤器。

| 轮  | 改了什么                                                                    |
| --- | --------------------------------------------------------------------------- |
| 43  | 删掉 17 个分区标题、发丝线、吸顶标题与 `subgrid` 结构，内容区变成单一流     |
| 44  | 条目从「6 列等宽文本行」改为「宽度随内容变化的胶囊」，整块 `justify-center` |
| 45  | 胶囊加分类色点：8 个低饱和色相 + 3 档明度，按分类顺序分配                   |
| 46  | 搜索结果复用同一面墙，删除 `ResultList` 组件                                |

实现要点：

- **色点不是随机色**。随机色每次构建都可能变，不携带信息；按主题取色让颜色成为分类编码，筛选后整屏同色即为确认。
- **8 个色相而不是 17 个**。17 个色相彼此只差约 21°，在 6px 的点上人眼分不开；8 个色相 + 明度分档更可辨。
- 未分组后，同色点连成的连续段落，就是「没有标题的分组」。

代价（明确记录）：全部视图的扫读效率低于分区视图，因为失去了标题作为锚点。

### 第四阶段·续：把「打开」画出来

| 轮  | 改了什么                                                                   |
| --- | -------------------------------------------------------------------------- |
| 47  | 每个胶囊右侧补回 `ArrowUpRight`（静态 30% 灰，hover 变品牌红并右移 0.5px） |

去掉分区之后，胶囊只剩「圆角 + 底色」在暗示可点；补上箭头后，**「点开、并且在别处打开」** 这件事重新变得可见。

代价：189 个内联 SVG 让首页 HTML 从 324K 涨到 408K（gzip 后约 1/5）。

## 第五阶段：把「一片纹理」做成「一块版面」

用户判断按钮区还差一档。诊断结论是四条：没有尺度对比、没有深度、颜色没有指代、对齐没有锚点。

| 轮  | 改了什么                                                                         | 对应哪条诊断 |
| --- | -------------------------------------------------------------------------------- | ------------ |
| 48  | 画布从纯白降到 `oklch(0.978)`，按钮改成白卡 + 1px 边框 + 双层阴影（静止 / 悬停） | 深度         |
| 49  | 全部左对齐，行首形成一条可追踪的竖线                                             | 对齐         |
| 50  | 字重 400 → 500，卡片高度 36 → 40                                                 | 按钮感       |
| 51  | 色点饱和度 0.09 → 0.07，不再抢品牌红                                             | 颜色         |
| 52  | 同一分类的按钮独立成块：块内 `gap-2`、块间 `gap-5`，**不加标题不加线**           | 节奏         |

第 52 轮是关键：直接用一个大 `flex-wrap` 时，189 个按钮是均匀纹理；按分类切成若干块、只靠 20px 的间距分隔，就出现了「段落」——眼睛有地方停，但页面上一个标题、一条分隔线都没有。每个块还带 `aria-label`，读屏用户能听到分类名，视觉上仍然没有。

**仍缺的一条**：尺度对比。189 个等权按钮不可能有主次，需要一个「精选」层——这要动数据（`featured` 字段），留待决定。

## 第六阶段：主题三态

| 轮  | 改了什么                                                                                 |
| --- | ---------------------------------------------------------------------------------------- |
| 53  | 工具栏加 `ThemeToggle`：shadcn `DropdownMenu` + 浅色 / 深色 / 跟随系统三选一，当前项打勾 |
| 54  | 图标随状态切换（太阳 / 月亮 / 显示器），并给按钮写上当前值的中文 `aria-label`            |

实现要点：

- `next-themes` 本来就在跑（`attribute="class"`、`defaultTheme="system"`），只是没有出口。这次只加了入口。
- 首帧用 `mounted` 守卫：服务端不知道用户偏好，先渲染显示器图标，挂载后再切，避免 hydration 不一致。
- 选择写入 `localStorage.theme`，刷新后保持；选「跟随系统」则回到 `prefers-color-scheme`。
