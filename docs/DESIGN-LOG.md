# 设计迭代记录

RedBot 首页从「卡片表格」演进到「高密度索引面板」的过程。每一轮都遵循同一循环：**改 → 构建 → 截图 → 评审 → 再改**，评审由一位独立的设计视角给出（10 分制）。

## 起点

单列布局 + 顶部 wrap 成两行的 pill 过滤 + 双行卡片（名称 + 描述）。功能完整，但信息语法只有一种：容器 + 两行文字，重复 189 次。

独立评审：**6.0 / 10**。诊断原话：「工程完成度高，设计判断缺席。」

## 关键决策与理由

**为什么是左侧导航，而不是顶部 pill**
17 个分类在 1200px 下要换行成两行，常驻占 72px；侧栏可以容纳 30+ 个分类而不增加首屏成本，且移动端由 `Sidebar` 免费提供 Sheet。

**为什么去掉条目的常驻边框**
189 个等大矩形会形成网格噪声，让页面读起来像表格。边界改由 hover 态（`bg-accent`）和常驻箭头承担——产品隐喻是「按钮」，不是「卡片」。

**为什么用 subgrid**
连续栅格能消除「最后一行只剩一个」的孤儿卡，但 `sticky` 需要正确的包含块。`grid-template-columns: subgrid` 同时满足两者：section 是真实盒子（吸顶随 section 结束而让位），子元素又对齐父级列。

**为什么不用逐条 Tooltip**
189 个 Radix Tooltip 会显著增加组件树。用原生 `title` + `aria-label` 达到同样目的（桌面悬停显示说明，读屏可读），零成本。

**为什么深色用 `foreground/85`**
189 行纯白字压在 `#0a0a0a` 上等于 189 个东西同时在喊「看我」。降低静止态亮度，hover 时回到全亮，让「注意」变成一种状态而不是默认。

## 已知取舍

- **Sheet 打开时的焦点**：Radix 会自动聚焦第一个可聚焦元素（「全部」），红色焦点环与选中态叠加，看起来像错误态。修它需要改 shadcn Sidebar 内部或包一层自定义逻辑，暂时接受。
- **移动端 2 列时的箭头**：箭头贴在单元格右缘，左列的箭头会落在屏幕中间。视觉上可接受，未做特例。
- **`pt-12` 的分区间距**：让「组内极密、组间极疏」成立，代价是单屏可见分区数从 4 个降到 3 个。

## 第四阶段：从「分区索引」到「按钮墙」

用户反馈：分区让人感觉页面被割裂，按钮应当不定宽、居中、有形状，搜索也只是一个过滤器。

| 轮  | 改了什么                                                                    |
| --- | --------------------------------------------------------------------------- |
| 43  | 删掉 17 个分区标题、发丝线、吸顶标题与 `subgrid` 结构，内容区变成单一流     |
| 44  | 条目从「6 列等宽文本行」改为「宽度随内容变化的胶囊」，整块 `justify-center` |
| 45  | 胶囊加分类色点：8 个低饱和色相 + 3 档明度，按分类顺序分配                   |
| 46  | 搜索结果复用同一面墙，删除 `ResultList` 组件                                |

实现要点：

- **色点不是随机色**。随机色每次构建都可能变，不携带信息；按主题取色让颜色成为分类编码，筛选后整屏同色即为确认。
- **8 个色相而不是 17 个**。17 个色相彼此只差约 21°，在 6px 的点上人眼分不开；8 个色相 + 明度分档更可辨。
- 未分组后，同色点连成的连续段落，就是「没有标题的分组」。

代价（明确记录）：全部视图的扫读效率低于分区视图，因为失去了标题作为锚点。

### 第四阶段·续：把「打开」画出来

| 轮  | 改了什么                                                                         | 对应哪条诊断 |
| --- | -------------------------------------------------------------------------------- | ------------ |
| 48  | 画布从纯白降到 `oklch(0.978)`，按钮改成白卡 + 1px 边框 + 双层阴影（静止 / 悬停） | 深度         |

**仍缺的一条**：尺度对比。189 个等权按钮不可能有主次，需要一个「精选」层——这要动数据（`featured` 字段），留待决定。

等宽网格只是「格子」对齐，格子内部还是居中的，所以 6 列箭头仍各自贴着文字飘。改成两端对齐后，箭头连成 6 条竖线，
名称也全部从同一 x 起排——表格感才真正成立。移动端因为是内容宽度，`flex-1` 无可用空间，布局不变。

## 第九阶段：设计系统重建（shadcn token 层）

不再逐处调数值，而是把「颜色 / 字号 / 圆角 / 阴影 / 间距」收进 token，组件只引用语义名。

| 轮  | 改了什么                                                                                                    |
| --- | ----------------------------------------------------------------------------------------------------------- |
| 70  | 中性色重排：背景 `0.985` / 卡面 `1.0` / 线条 `0.925`，三层靠明度差区分                                      |
| 71  | 品牌红下沉到 `oklch(0.547 0.186 27)`（白字对比 > 5:1），深色模式用 `0.66` 提亮                              |
| 72  | 字号阶梯 token 化：`2xs 11 / xs 12 / sm 13 / base 14 / md 15 / lg 18 / xl 22 / 2xl 28 / 3xl 32`，全部带行高 |
| 73  | 阴影 token：`--shadow-xs/sm/md` 统一走低透明度冷灰，按钮用 xs、悬停用 sm                                    |
| 74  | 间距重排：页头 64（移动端 56）、主区左右 20/32、标题上 56/下 40、分组间距 32                                |
| 75  | 按钮：`rounded-lg` + `border` + `shadow-xs`，文字 `text-base`（14），hover 只变色不位移                     |
| 76  | 报头：计数徽章改中性灰（红色只留给「当前分类」），状态行 12px / 70%                                         |
| 77  | 深色模式：侧栏 active 用 `bg-primary/15`，避免暗底上的红调发浊                                              |

原则：**同一屏里红色只出现在一个地方**——当前分类，其余用明度差表达层级。

## 第十阶段：足迹页

用户点过的链接自动沉淀成「我的页面」，放在侧栏「全部」上方。

| 轮  | 改了什么                                                                                      |
| --- | --------------------------------------------------------------------------------------------- |
| 80  | `lib/history.ts`：localStorage 存 `{id, at, count}`，上限 300 条，同标签页 + 跨标签页都能同步 |
| 81  | `LinkPill` 点击时 `recordVisit`，不阻塞跳转（`localStorage` 写失败静默）                      |
| 82  | `/history/` 路由 + 侧栏「🐾 足迹」入口（带计数，位置在「全部」之上）                          |
| 83  | 页面复用按钮墙的视觉语言，但点击进入「管理态」时变成多选                                      |
| 84  | 批量：全选 / 删除选中（带计数）/ 清空（两步确认）/ 完成                                       |

设计取舍：

- **删除不进详情页**，直接在墙上多选，因为足迹本身就是一屏能看完的列表。
- **清空要两次点击**，且 4 秒后自动复位，避免误触。
- 足迹为空时不显示徽章，只留一句引导。

## 第十一阶段：侧栏形态

参考 chat.deepseek.com 的侧栏骨架：**品牌行 + 折叠 → 一个主操作 → 分组标题 → 滚动列表**。

| 轮  | 改了什么                                                                                     |
| --- | -------------------------------------------------------------------------------------------- |
| 85  | 品牌行右侧加折叠按钮，桌面可收成 48px 图标轨（`collapsible="icon"`），图标模式下文字自动隐藏 |
| 86  | 主操作换成「随机一个」——随机打开一个信息源并计入足迹，比「新会话」更贴合目录产品             |

取舍：侧栏内容超过一屏后**允许滚动**（和参考站一致），页脚固定在底部；折叠态保留 emoji 作为图标。

## 第十二阶段：报头不再空洞

原来的报头是「标题 / 说明 / 统计」三行递减的灰字，横向完全没有内容，在大屏上像一片空白。

| 89  | 左侧加 44px 图标锚点（分类 emoji），与侧栏、主题索引形成同一符号系统                |
| 90  | 统计移到右侧两行（`N 个主题` 可点 + `更新于`），与标题形成左右张力                  |
| 91  | 去掉报头里的「189 个信息源」——徽章已经显示数量，重复只是噪音                        |
| 92  | 底部加 1px 细线，把「页头」和「按钮墙」分开；高度从 `pt-14 pb-10` 收到 `pt-10 pb-6` |

原则：**报头只放这一页特有的信息**，全站恒定的数字（总条数、主题数、更新时间）放右侧弱化，不占主视线。
