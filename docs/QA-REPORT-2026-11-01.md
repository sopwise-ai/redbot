## 3. 发现的问题

### 问题 #1 [P1] 移动端（390px）侧栏抽屉：首次点分类偶发被吞，需二次点击

- **复现步骤**：viewport 390×844 → 打开首页 → 点「Toggle Sidebar」展开抽屉 → **立即**点「新闻 17」
- **期望**：切换到 `/topics/news/`（或客户端等效状态），H1 变「新闻」，pill 数 17
- **实际**：约半数概率点击无效——抽屉收起（`sidebar data-state="closed"`），但 URL 仍为 `/`、H1 仍为品牌句、pill 数 189（全量）。**重开抽屉再点一次即成功**（实测：新闻第 2 次成功、科技第 1 次成功、娱乐成功）。桌面端（1440px）侧栏切换 100% 正常，仅移动端抽屉复现
- **证据**：失败样本 `{"url":"http://localhost:4173/","h1":"中文互联网精选网站清单","pillCount":189,"sidebarState":"closed"}`；成功样本 `{"url":"http://localhost:4173/topics/news/","h1":"新闻","pillCount":17}`；同一序列内两次点击结果不同（第一次吞掉、第二次生效），非稳定逻辑
- **疑似方向**（未改码，仅观察）：抽屉展开动画期间（约 200ms 内）坐标点击落在移动中的元素上；`select()` 里 `setOpenMobile(false)` 与 `onSelect` 的时序竞态

### 问题 #2 [P2] 移动端抽屉选完分类后，body 滚动锁（overflow:hidden）偶发未释放

- **复现步骤**：390×844 → 打开抽屉 → 点分类（切换成功的那次）→ 尝试 `window.scrollTo(0, 300)`
- **期望**：抽屉关闭后页面恢复可滚动
- **实际**：一次实测中切换成功（`/topics/news/`、17 pill）但 `getComputedStyle(document.body).overflow === "hidden"`，`scrollTo` 无效（scrollY 恒 0），`sidebar data-state="open"`、`overlayCount: 0`、侧栏 rect 已滑出视口（left -288）——即视觉已关、状态与滚动锁未同步。另一次成功切换后 overflow 恢复正常可滚动。与问题 #1 同源（抽屉开合状态机在快速操作下不稳定）
- **证据**：`{"sidebarLeft":-288,"sidebarState":"open","bodyOverflow":"hidden","overlayCount":0}` + `{"scrollY":0,"canScroll":false}`

### 问题 #3 [P3] skip link 按 Esc 后仍留在 DOM（视觉已隐藏）

- **复现步骤**：body 焦点按 Tab（skip link 挂载并聚焦）→ 按 Esc
- **期望**（AGENTS.md 口径「平时不进 DOM」）：Esc 后卸载或至少下次 Tab 重新走挂载流程
- **实际**：`document.getElementById('skip-link')` 仍存在，但 `offsetParent: false`（`fixed` + 无焦点样式，视觉不可见、不占布局）；只有点击它跳转（`onClick`）才会 `setSkipReady(false)` 卸载。继续 Tab 焦点正常流向侧栏（「🐾足迹0」），无焦点卡死
- **影响**：极小——不影响键盘导航与布局，属口径与实现的轻微偏差

### 问题 #4 [P2] 客户端路由切换后焦点未交给 `#content`（键盘焦点落在 BODY）

- **复现步骤**：首页 → 点击侧栏「足迹」（`router.push('/history/')`）或报头「17 个主题」链接（Next Link 客户端导航）
- **期望**：`document.activeElement === main#content`（app-shell.tsx:162-173 的 pathname effect）
- **实际**：多次实测（等待 0.6–1.5s、focusin 监听 0 次触发、focus() 调用日志仅见 Next 内部 DIV 一次）`document.activeElement` 均为 `BODY`。原因分析：该 effect 依赖 `usePathname()` 变化，但站内大部分导航用 `replaceUrlQuietly`（app-shell.tsx:114-128 注释明言绕过 Next 的 patch，`usePathname` 不感知）；`router.push` 场景下 effect 依赖数组 `[pathname]` 理应触发，但实测也未观察到 `main.focus()` 生效（focus 事件 0 次）——怀疑 `mounted.current` 短路或 timeout 被 Next 的焦点管理覆盖
- **影响**：路由切换后键盘用户 Tab 会从页面顶部重新开始，而非从主内容继续；屏幕阅读器用户失去「新页面已加载」的焦点提示。**缓解**：main `tabindex="-1"` 本身可聚焦（手动验证通过），skip link 机制仍可用
- **证据**：`{"url":"http://localhost:4173/topics/","active":"BODY","mainFocused":false,"mainTabindex":"-1"}`；`focusLog` 仅 1 条 `{tag:"DIV"}` 无 main；`mainFocusEvents: 0`

其余检查点未发现功能缺陷；未发现任何 Next.js 报错浮层、白屏或控制台可见错误（agent-browser 各页 open/snapshot 均无错误输出，`nextjs-portal` 全站 0 命中）。

## 4. 结论与建议

### 整体质量判断

- **构建与静态导出**：健康。28 页全部生成，CI 口径断言（193 ≥ 100 个 `target="_blank"`）远超门槛；manifest/robots/sitemap 齐全且内容正确。
